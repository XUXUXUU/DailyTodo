# Daily Todo 1.16.0 测试报告

版本 1.16.0（27），原生交互验收于 2026-11-07，最终检查与交付于 2026-11-09。保留原 SwiftUI 工程、提醒与全部用户数据；本轮不测试发送消息。正式安装为用户自行更新的 v1.15.0（26），不会被验收构建覆盖。

## 产品判断与参考

自动续接适合这里：授权是完成转发设置的前置步骤，成功后无需再点一次“继续设置”。助手收起后回到原转发卡片，不替用户保存方式、开启转发或发送消息。已经切去其他软件时安静收起，以免抢焦点。

参考 [Apple Onboarding 指南](https://developer.apple.com/design/human-interface-guidelines/onboarding) 的简短、上下文内学习原则，以及 [Raycast Screen Awareness](https://manual.raycast.com/ai/screen-awareness) 对授权后续接原设置位置的说明。[1Password Universal Autofill 设置](https://1password.com/features/how-to-use-universal-autofill-on-mac)也将权限作为继续使用功能的前提。自动聚焦的边界是本应用的产品选择，并非声称这些产品都采用相同的跳转实现。

“在访达中显示”采用 macOS 常见动作名称，参考 [Apple 的 Finder 操作说明](https://support.apple.com/en-eg/guide/mac-help/mchlp1046/mac)，以文件夹图标、白色按钮底、蓝色文字、边框和悬停反馈体现可操作性。

## 修改文件

- `Sources/AccessibilityGuide.swift`：显式按钮组件、助手自动关闭与恢复前台、移除助手状态和继续按钮；先完成一次性续接，再处理外侧定位和隐藏分支。
- `Sources/AccessibilityPermissionPolicy.swift`：单次续接状态，手动关闭取消，其他应用前台仅安静关闭。
- `Sources/FeishuAutomation.swift`：已授权时在打开系统设置之前短路，避免晚到的设置窗口覆盖原卡片。
- `Sources/AutomationSettings.swift`：恢复弹出框复用相同的访达按钮。
- `Tests/AccessibilityPermissionTests.swift`：未授权、不打开不返回、返回一次、安静关闭、取消与重新开启等回归。
- `Info.plist`、`App.swift`、`README.md`、发布说明：版本和行为说明。

## 原生续接验收

- 实际授权前，`access/current/fresh` 均为拒绝，助手没有提前完成。
- 用户在本机解锁后切回 Codex 时，助手执行 `close-quietly`，`appActive=false`、前台仍为 Codex、`helperOpen=false`，没有抢焦点。
- 最终测试构建中，从系统设置重新添加测试程序并授权后，执行 `return-to-app`，`appActive=true`、前台为测试程序、`helperOpen=false`；原转发卡片保持，两个方式都未被擅自选中。
- 再次测试时先选择“自动发送”但不保存，临时撤销并恢复测试权限；助手关闭并返回后，“自动发送”仍为已选择。没有点击保存或测试发送，不改变持久配置和正文。
- 本轮没有发出任何飞书测试消息。助手不再保留“已开启 / 继续设置”完成页；主卡片自身的真实权限提示保留。
- 该次测试结束后测试进程已退出；2026-11-09 再次核对并撤销残留测试授权，正式版权限保持开启。

## 范围与边界

未更改权限判定方法、通知调度、收件人、转发模式或保存格式，保留 21 条文案。系统设置需要用户本机解锁时，程序不会绕过密码或伪造授权。仍采用临时签名，升级后旧授权可能需重新添加。

Intel/macOS 13 实机、其他 Space/多屏下的全部焦点时序、直接拖图标进系统权限列表，以及所有授权系统弹窗组合不作为本轮已实测结果。最终清理已归档验证后移除 8 份构建、测试和本地验收 App，备份清理 3 个隔离测试配置域及附属缓存；系统搜索仅剩正式安装，测试通知和 LaunchAgent 均为零。2026-11-09 清理前后正式数据哈希一致，没有回滚跨日正常使用产生的数据。公开包下载核验另附。

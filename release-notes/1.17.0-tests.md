# Daily Todo 1.17.0 测试报告

版本1.17.0（28），2026-11-09，macOS26.4.1 / Apple Silicon。直接修改原SwiftUI工程；正式安装1.16.0（27）未被测试构建覆盖。

## 原因与修复

1. 原先深度优先读取整个飞书窗口，长云文档会先消耗1200个节点的额度，导致后面的头像/联系人搜索入口缺失。正式1.16已实测“打开长文档→本人测试误报登录；关闭文档侧栏→同版填写成功”。新版只展开必要的搜索、账号卡片、聊天WebArea，并按广度读取，保留原生侧栏控件。
2. 权限探测以前采用第一个非未知结果。记录曾出现current/fresh均true但飞书目标连接denied、其他进程允许。新版综合有限数量的探测，并单独要求飞书目标连接未拒绝；目标拒绝或连接未刷新时明确“重启继续”。撤销后旧连接仍可能可读，因此还要求当前进程、后台探测与新进程授权一致。后台操作使用最多6秒有效的同步授权快照，转发期间每2秒更新，仍逐次独立校验飞书权限。
3. 新聊天编辑器在挂载过程中可先出现标题和输入区，随后才提供可验证的只读占位及编辑属性。此前会过早判断“有草稿”。新版最多等待8秒，必须真正通过原有空输入框验证才继续；未知、真实草稿、附件、焦点变化仍停止。
4. 独立复审发现，部分读取的树不能用于判断“没有草稿/附件”。新版明确携带完整性结果，节点或深度截断会停止操作。实测飞书正常聊天深度44层，超过原35层限制；新深度上限128，节点上限仍1200。
5. 授权图示分开“添加”和“移除”：添加画出访达应用、拖拽动作和系统列表；移除画出选中系统列表行及下方减号，移除阶段不再显示访达按钮。访达前台时助手保持可见，实际授权成功才收起。

## 修改文件

- `Sources/AccessibilityGuide.swift`：两类独立图示、移除/添加切换、访达期间保持助手可见；428×204pt外侧助手。
- `Sources/AccessibilityPermission.swift`、`AccessibilityPermissionPolicy.swift`：有界多进程探测与结果合并、Finder流程判断。
- `Sources/AutomationSettings.swift`：恢复入口直接打开外侧移除指引，删除混合弹出框。
- `Sources/FeishuAutomation.swift`、`FeishuAutomationPolicy.swift`：限定范围的广度读取、完整性保护、输入框就绪等待、隔离测试诊断。
- `Tests/FeishuAutomationTests.swift`、`AccessibilityPermissionTests.swift`：大型文档、深层历史、截断、权限合并等回归。
- `Info.plist`、`README.md`、发布说明：版本与使用说明。

## 未覆盖与边界

- 没有向何雪瑶发送测试消息；正式收件人固定值及共用主按钮路径由策略检查和强制本人路由验证，不宣称已经向正式收件人实发。
- 本轮没有取得跨窗口拖拽被系统接受的端到端证据。实测系统“＋”添加测试程序后开关直接开启，但不把这个结果推断为所有拖拽场景或所有macOS版本都自动开启。指引始终使用“开关若未开启，再点一下”，真实权限成功即结束。
- 未在一台全新Mac、Intel实机或macOS13实机测试；Intel仅完成编译。未重测所有中文输入法、休眠唤醒与通知长期运行场景；相关旧逻辑保留，现有单元回归通过。
- 飞书没有独立服务器送达回执；报告中的发送成功表示观察到消息与输入框清空。临时签名机制保持，升级后旧辅助功能条目仍可能需要按新图重新添加。
- 本轮中间构建遇到的前台切换、账号卡片读取超时、输入区过早判断和深度截断，均未当作通过；最终构建以上表及保存的验收记录为准。
